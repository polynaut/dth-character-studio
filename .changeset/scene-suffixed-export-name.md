feat(rom): Houdini-ready export layout. Two changes to where and how the DTH export lands:

- **Scene-suffixed export names** — the figure name handed to the DTH Exporter is now scene-suffixed at run time: `Kira` exporting from the `summertide` scene writes `Kira_Summertide.abc`/`.dth` (subfolder capitalized; matching reference-skeleton FBXs too) instead of yet another `Kira.*`, so the per-scene export subfolders no longer all hold identically-named files. The primary scene keeps the plain name (`Kira.abc`, never `Kira_Primary.abc`) while still exporting into its subfolder. The **delivered PoseAsset CSV is renamed the same way** (`Kira_Summertide_pose_asset.csv`) so one export folder never mixes naming patterns — the source CSV in the character folder keeps its name. The CSV's bone-scale reference-FBX paths follow via a new `{{DTH_EXPORT_NAME}}` token resolved by the same run.
- **Houdini project folder** (schema v27) — a new field on the Export directory pane. When set, everything exports into `<export dir>/<folder>/dth-export/<scene subfolder>/` — Set-Project a Houdini project to `<export dir>/<folder>` and import via `$JOB/dth-export/primary/Kira.dth`. Overridable per Daz scene (including to empty = that scene exports flat). New characters seed `<Project>_<Character>`; existing characters keep the flat layout untouched until they opt in.
- **Export-folder housekeeping** — every character records which export folders its layout generates, and on the next save after a layout change (renamed/cleared project folder, moved scene subfolder) the previous layout's folders are removed from the export directory. Only recorded folders inside the current export directory are ever touched; clearing the export directory deletes nothing.
- **`$DAZ3D_LIB` in houdini.env** — with My DAZ 3D Library and the Houdini documents folder(s) set, the studio maintains a `DAZ3D_LIB` variable in each configured `houdini.env`, so Houdini networks can reference Daz library files as `$DAZ3D_LIB/…` instead of hardcoded machine paths. Kept current on every Settings save and by Tools → Refresh assets; applies on the next Houdini start.
- **Opening linked scenes/projects now matches an Explorer double-click** — a `.hip`/`.duf`/`.uproject` opened from the studio is handed to the OS shell (Explorer) instead of being launched from the studio's own process, so the app starts with the normal user environment. This fixes Houdini projects opened from the studio missing the DazToHue shelf (Houdini had resolved its preferences folder from the studio's inherited environment).
- **Dedicated bulk script for DTH Export** — job-file rows now run a hidden `.Bulk_ROM_Export.dsa` (generated whenever an export directory is set): it always builds the ROM and always exports everything — skeleton/mesh and every hair asset — no matter the "Run the export with the ROM script" / "Export hair assets too" toggles. The v38 `bulk-export` script argument is retired (it never reached the script through the Runner), and the visible ROM script carries an export block only in combined mode again.
- **Job-file contract v2 (JSON + live progress)** — the DTH Export handoff is now a JSON job file. The Runner renames it (`running_` prefix) when it starts — so an untouched handoff can still be aborted, a renamed one is running — and keeps the file's `progress` (0–100) and per-scene statuses current as it works. The studio simply polls that file: the button shows "Exporting n%", and at 100% the studio deletes the file and toasts the outcome (including failed scenes). The old export-folder watching is gone. **Requires Runner v1.0.5+.**

- **Generate Houdini projects** — with the export directory + Houdini project folder set, the character page's Houdini projects section gains **Generate project**: hython creates a new scene with the DazToHue network instantiated from your *installed* DazToHue HDA (always the current version — no template file to rot), bakes *Set Project* to `<export dir>/<project folder>` (seeded with its `dth-export/`) and saves the scene in the houdini folder next to it — open it in Houdini and everything imports `$JOB`-relative, network already in place. One one-time Settings entry: the Houdini installation folder. Removing a generated project offers a **Keep houdini files** toggle (on = unlink only; off = the scene file and project folder are deleted); missing project files on disk are detected and shown with an Unlink action.
- **ROM scenes stay reopenable** — after a clean ROM build (and before any export), every ROM-building script saves the scene as `<scene>_ROM.duf` into a hidden `.ROM_Animations/` folder next to the scene file, so a generated ROM animation can be opened again later without the slow rebuild. One file per scene, overwritten on each run.

Runtime v40 — Tools → Refresh assets regenerates existing scripts + CSVs.
