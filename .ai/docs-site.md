# The docs site — what "the docs page" means

When the user says **"the docs page" / "the docs site"**, they mean the public
**GitHub Pages site** deployed out of this repo's markdown docs:
<https://polynaut.github.io/dth-character-studio/> — a landing page plus the
rendered user guide. It is **not** an in-app route: the app's topbar "Docs"
button (`apps/web/src/components/header-nav.tsx`, `DOCS_URL`) simply opens the
guide externally.

## The pieces

| Piece | Source | Notes |
|---|---|---|
| Landing page | `site/` (`index.html`, `main.js`, `styles.css`) | Plain hand-written static HTML/CSS/JS — no framework, no bundler, no npm deps. Dark-only by design. Design tokens live in `site/styles.css` `:root`. |
| Guide content | `docs/guide/*.md` | **Single source of truth** — the same files render on GitHub. Every page must start with an `# ` title line. |
| Guide build | `scripts/build-guide-site.mjs` (`pnpm build:guide`) | Renders `docs/guide/*.md` → `site/guide/*.html` (gitignored, built at deploy time). Re-skins the markdown with the landing page's styling + a sidebar. |
| Guide chrome | `site/guide.css`, `site/guide.js` | Shared by all generated guide pages (lightbox, anchor copying, sticky headings, search, direct-download button). |
| Screenshots / clips | `docs/guide/screenshots/`, `docs/guide/clips/` | Generated by the Playwright suite (`apps/web/smoke/guide.screenshots.ts`, `guide.clips.ts`; `pnpm screenshots` / `pnpm clips`) against the real SPA. |

Heads-up: `pnpm lint` covers only `apps packages` — `site/` and `scripts/` are
**not** linted. `site/guide.js` and `main.js` are hand-maintained plain browser
JS; keep them dependency-free.

## Build guards (all fail the build, deliberately)

`build-guide-site.mjs` enforces:

- **NAV placement** — every `docs/guide/*.md` must be listed in the script's
  `NAV` (sidebar order), and every NAV entry must exist on disk.
- **Asset coverage** — screenshots/clips/gifs referenced by a page must exist,
  and none may be orphaned; plus an output-side re-check that each referenced
  asset actually landed in `site/guide/` (catches a dropped `cpSync`).
- **Search extraction** — every page must yield at least one search-index entry
  (see below); zero entries means the heading markup and the index extractor
  drifted apart.

## Deploy & previews

- **Production**: `.github/workflows/pages.yml` — on `main` push touching
  `site/**`, `docs/guide/**`, or the build script, runs `pnpm build:guide` and
  deploys `site/` to GitHub Pages.
- **PR previews**: `.github/workflows/site-preview.yml` — PRs touching the same
  paths get a Cloudflare Pages preview (`pr-<N>.dth-character-studio.pages.dev`,
  sticky PR comment + GitHub deployment box). Production hosting stays on
  GitHub Pages; Cloudflare only serves previews. Keep the two workflows' `paths`
  lists in sync.

## Guide search

Docs-style client-side search over the whole guide — no external service, no
runtime dependency:

- **Index**: built by `build-guide-site.mjs` into `site/guide/search-index.json`
  — one entry per heading section (`{page, title, level, id, heading, text}`),
  cut from the same rendered HTML the pages ship with, so every entry
  deep-links to a real anchor id. Adding a page/section needs no extra step.
- **UI**: `site/guide.js` — topbar button (baked into the shell by the build
  script), Ctrl/⌘+K or `/` to open, ↑/↓ + Enter to navigate, Escape closes.
  Fetches the index once on first open. Scoring: query words AND-match;
  word-start heading hits > heading > page title > body; whole-phrase bonus for
  multi-word queries; small level bonus floats a page's own entry over its
  subsections. Result rows render via DOM nodes + `<mark>` (no innerHTML of
  index text). Styling in `site/guide.css` ("Search" section).
- **Gotcha (measured)**: `str.split(/(?=<h)/)` yields **no** leading empty
  chunk when the string starts at the delimiter — an unconditional `.slice(1)`
  after such a split silently dropped every page's h1 entry. The extractor now
  keeps all chunks and lets the heading regex reject non-heading ones; the
  per-page ≥1-entry guard exists precisely to catch this class of drift.

## Anchor landing & image layout shift

Deep links (`page.html#section` — hand-shared or from search) used to land
"randomly": the browser scrolls before the big screenshots load, then each
finished image pushes the target down. Two-part fix, keep both halves intact:

- **Build time**: `reserveImageSpace` in `build-guide-site.mjs` stamps EVERY
  `<img>` with `style="aspect-ratio: W / H"` — local assets
  (screenshots/clips/gifs) read from disk, external ones (GitHub
  user-attachments URLs) fetched once per build. Dimensions come straight from
  the image bytes, sniffed by magic number (PNG IHDR, GIF logical screen, WebP
  VP8X/VP8/VP8L) — no image library. Boxes get their height at first paint, so
  the native anchor scroll is already exact. A failed external fetch only warns
  (never fails the build) and skips that stamp.
- **Load time**: `revealHashTarget` in `site/guide.js` re-scrolls the visited
  hash after `load` (and opens a targeted accordion) — the fallback for an
  external image whose build-time fetch failed.
